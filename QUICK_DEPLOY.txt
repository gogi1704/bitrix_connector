BITRIX CONNECTOR — КОРОТКАЯ УСТАНОВКА НА СЕРВЕР
================================================

Предполагается:
- сервер: root@213.148.9.40
- домен: chelovecbitmax.ru
- anketa_bot_max уже находится в /root/anketa_bot_max_web
- Google-ключи уже лежат в /root/anketa_bot_max_web/docs


1. ПОДКЛЮЧИТЬСЯ К СЕРВЕРУ
-------------------------

export DOCKER_API_VERSION=1.43

5. СОБРАТЬ ОБРАЗ
-----------------

cd /root/bitrix_connector

docker build -t bitrix_connector_image .


6. УДАЛИТЬ СТАРЫЙ КОНТЕЙНЕР
---------------------------

docker rm -f bitrix_connector 2>/dev/null || true


7. ЗАПУСТИТЬ КОНТЕЙНЕР
----------------------

docker run -d \
  --restart always \
  --name bitrix_connector \
  --env-file /root/bitrix_connector/.env \
  -p 127.0.0.1:8001:8000 \
  -e SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt \
  -e REQUESTS_CA_BUNDLE=/etc/ssl/certs/ca-certificates.crt \
  -v /root/bitrix_connector/storage:/app/storage \
  -v /root/anketa_bot_max_web/docs:/external/anketa_bot_max/docs:ro \
  -v /etc/ssl/certs/ca-certificates.crt:/etc/ssl/certs/ca-certificates.crt:ro \
  bitrix_connector_image

9. NGINX
--------

apt update
apt install nginx certbot python3-certbot-nginx -y

nano /etc/nginx/sites-available/bitrix-connector

Вставить:

server {
    listen 80;
    server_name chelovecbitmax.ru;

    client_max_body_size 50m;

    location / {
        proxy_pass http://127.0.0.1:8001;
        proxy_http_version 1.1;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_connect_timeout 60s;
        proxy_read_timeout 60s;
    }
}

Активировать:

ln -sf /etc/nginx/sites-available/bitrix-connector /etc/nginx/sites-enabled/bitrix-connector

nginx -t
systemctl reload nginx

Получить HTTPS-сертификат:

certbot --nginx -d chelovecbitmax.ru

Проверить:

curl https://chelovecbitmax.ru/health


10. НАСТРОИТЬ BITRIX И MAX
--------------------------

Локальному приложению Bitrix24 дать права:
imopenlines, imconnector, im, disk.

Права im и disk нужны для передачи файлов из Bitrix24 в MAX.

В настройках приложения указать обработчик установки:

https://chelovecbitmax.ru/bitrix/install?install_token=ВАШ_BITRIX_INSTALL_TOKEN

BITRIX_INSTALL_TOKEN — секрет, который вы сами сгенерировали и записали в .env.
BITRIX_APPLICATION_TOKEN вручную получать и заполнять не нужно: Bitrix24 пришлёт
его вместе с access_token и refresh_token, а коннектор сохранит всё в
/root/bitrix_connector/storage/oauth.json.

После этого переустановить приложение в Bitrix24.

Проверить, что Bitrix24 прислал токены, не выводя их значения:

docker exec bitrix_connector python -c "import json; d=json.load(open('/app/storage/oauth.json')); print({k: bool(d.get(k)) for k in ('access_token','refresh_token','application_token')})"

Ожидается:
{'access_token': True, 'refresh_token': True, 'application_token': True}

В терминале сервера указать тот же CONNECTOR_ADMIN_TOKEN, который записан в .env:



Важно: для curl используется переменная ADMIN_TOKEN. Простая команда
CONNECTOR_ADMIN_TOKEN=... не изменяет переменные уже запущенного контейнера.

Подключить событие сообщений операторов:


export ADMIN_TOKEN='90670eed41fbd1bc1b515869a16bec3ce15a8eb36f3d0a43c610bd3cd715b448'
curl -X POST \
  -H "X-Connector-Admin-Token: $ADMIN_TOKEN" \
  https://chelovecbitmax.ru/bitrix/openlines/test/bind

Подключить MAX-коннектор и webhook:

curl -X POST \
  -H "X-Connector-Admin-Token: $ADMIN_TOKEN" \
  https://chelovecbitmax.ru/bitrix/max/setup

Проверить обработчики:

curl \
  -H "X-Connector-Admin-Token: $ADMIN_TOKEN" \
  https://chelovecbitmax.ru/bitrix/openlines/test/handlers


11. ПРОВЕРИТЬ КОМАНДЫ МЕНЕДЖЕРА
-------------------------------

В открытой линии Bitrix написать:

/anketa

Команда пользователю MAX не отправляется.

После успешной отправки обычного сообщения в MAX коннектор отдельно подтверждает
Битриксу статус доставки. Если Bitrix временно недоступен, повторяется только
статус, а сообщение пользователю повторно не отправляется.

Принудительно повторить поиск в Google:

/anketa_refresh

Доступные команды:

/help
/client
/anketa
/anketa_refresh
/results
/summary
/summary_all
/remind 2h Проверить результаты
/tag повторный
/tag ожидает_результаты
/tag срочный
/tag нужна_консультация
/history
/history 1
/analytics
/chat_complete

/chat_complete переносит рабочие сообщения диалога в таблицу chat_archives
в storage/connector.db и очищает таблицу messages только для этого диалога.
История сообщений в самом Bitrix24 и MAX не удаляется.

/summary использует ИИ, если настроены SUMMARY_AI_*, иначе строит локальное
резюме. /summary_all пакетно обрабатывает текущий диалог и все архивы только
текущего клиента. Перед отправкой в ИИ телефоны и email обезличиваются.
/remind поддерживает m (минуты), h (часы), d (дни). Напоминание переживает
перезапуск контейнера и появляется только в диалоге менеджера в Bitрикс.
/history показывает архивы только текущего клиента.

Панель аналитики:

https://chelovecbitmax.ru/analytics/

Логин: admin
Пароль: значение CONNECTOR_ADMIN_TOKEN из .env

Панель содержит только агрегаты. В ней можно повторно поставить в очередь
задачу, которая исчерпала автоматические попытки. Payload такой задачи хранится
до JOB_FAILED_RETENTION_DAYS дней, затем удаляется автоматически.
